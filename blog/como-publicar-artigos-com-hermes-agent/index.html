Como Publicar Artigos com Hermes Agent

📅 30 Jul 2026 📖 4 min de leitura 🏷️ Tutorial ✍️ Marcus

O Hermes Agent é a ferramenta ideal para automatizar a publicação de conteúdo no teu blog. Neste tutorial, vais aprender o processo completo: desde a criação de uma skill até ao deploy automático.

O que vais precisar

  • Hermes Agent instalado (ou acesso CLI)
  • Um repositório GitHub para o blog
  • GitHub Actions no repositório com deploy para Cloudflare Pages
  • Modelo de IA configurado (Gemini, Claude, etc.)

Passo 1: Criar a skill de geração

No diretório ~/.hermes/skills/, cria a pasta gerar-post com o ficheiro SKILL.md:

---
name: gerar-post
description: Gera um post para o blog
author: MarctechJA
version: "1.0"
platforms:
  - macos
  - linux
  - windows
metadata:
  hermes:
    tags: [blog, escrita]
---

# gerar-post

Gera um post completo para o blog.

## When to Use
Quando o utilizador precisa de um novo artigo de blog.

## Instruções
1. Recebe o tópico do artigo.
2. Escreve um artigo completo em português de Portugal.
3. Devolve o conteúdo pronto para publicação.

## Critérios de conclusão
- O artigo é completo, sem cortes e cobre o tópico pedido.

Depois, podes usar a skill diretamente no chat:

hermes chat -s gerar-post "Escreve um artigo sobre automação no Hermes Agent"

Passo 2: Script de publicação

Cria um script que recebe o HTML gerado e trata de:

  1. Criar o diretório com o slug correto
  2. Gerar meta tags SEO automaticamente
  3. Atualizar o arquivo do blog (blog/index.html)
  4. Fazer commit e push para o GitHub

Passo 3: Automatizar com GitHub Actions

Adiciona um workflow .github/workflows/publicar.yml:

name: Publicação Automática
on:
  schedule:
    - cron: '0 9 * * *'
  workflow_dispatch:

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Gerar e publicar
        run: |
          pip install -r requirements.txt
          python scripts/generate-post.py
          bash scripts/post.sh "Título" "Categoria" "Autor" /tmp/artigo.html

Passo 4: Executar manualmente

No GitHub, vai a Actions > Publicação Automática > Run workflow. O script gera o conteúdo e faz o deploy.

Dicas para conteúdos de qualidade

  • Prompt bem definido: instrui o modelo sobre o tom, público-alvo e estrutura
  • Revisão automática: adiciona um passo extra na skill para verificar ortografia e SEO
  • Rotação de tópicos: mantém uma lista de temas para variar o conteúdo

Com este sistema, o teu blog pode ter conteúdo novo todos os dias sem trabalho manual. O Hermes Agent trata da criatividade, o GitHub Actions trata da consistência.

O que o script de publicação deve fazer

O script é a peça que liga o conteúdo gerado ao site final. Na prática, ele:

  1. Cria o slug — converte o título num URL limpo (por exemplo, "Como Publicar Artigos" → /blog/como-publicar-artigos-com-hermes-agent/).
  2. Gera o HTML — aplica o template da página com cabeçalho, artigo, sidebar e rodapé.
  3. Constrói as meta tags — título, description, Open Graph e canónico, a partir do conteúdo gerado.
  4. Atualiza o arquivo — insere o novo card no blog/index.html, pela ordem mais recente primeiro.
  5. Atualiza a homepage — mantém no máximo os seis cards principais.
  6. Atualiza o sitemap — adiciona o URL novo para facilitar a indexação no Google.
  7. Faz commit e push — e o Cloudflare Pages trata do resto.

Pipeline de qualidade

Automatizar não significa publicar tudo sem filtro. Antes do commit, vale a pena validar:

  • Ortografia e fluidez — o prompt deve instruir o modelo a escrever em português de Portugal, com tom consistente.
  • Completude — rejeitar conteúdo cortado a meio, como um passo de tutorial interrompido ou um bloco de código sem fecho.
  • Limpeza do HTML — sem comentários, sem headings desnecessários e com a meta description completa.
  • Execução dos exemplos — se o artigo mostra código, o código deve funcionar; um exemplo partido quebra a confiança do leitor.

Idealmente, o script corre estas verificações e só faz o push quando passam — tal como um teste automatizado num projeto de software.

Erros comuns e como evitá-los

  • Ficheiros em diretórios temporários — guarda sempre o código do blog no repositório; se usares /tmp, perdes tudo ao reiniciar o ambiente.
  • Falhas da API sem retry — as APIs de IA podem responder devagar ou falhar; o script deve tentar vários modelos e modelos alternativos antes de desistir.
  • Dependências não declaradas — o workflow do GitHub Actions deve instalar explicitamente as dependências (por exemplo, pip install -r requirements.txt).
  • Cache do navegador — ao atualizar CSS, usa um ?v=YYYYMMDD no link, senão os leitores veem a versão antiga.

Perguntas Frequentes

Preciso de GitHub Actions obrigatoriamente?

Não. Podes correr o script localmente sempre que quiseres publicar. O GitHub Actions apenas adiciona o agendamento diário e a consistência.

Como evito repetir temas?

Mantém uma lista de tópicos em rotação sequencial e um registo dos já publicados. O script escolhe o próximo tema da fila e avança — sem repetir.

E se o artigo gerado ficar com erros?

Ativa a validação automática antes do push: se o artigo falhar os testes, o script regenera-o. Em último caso, o commit não acontece e o erro fica visível no histórico.

Conclusão

Publicar com o Hermes Agent e o GitHub Actions é um processo completo e repetível: a skill gera o conteúdo, o script transforma-o em páginas válidas e o GitHub faz o deploy. Com validação de qualidade e monitorização, o teu blog publica todos os dias — e tu só precisas de rever o resultado.
